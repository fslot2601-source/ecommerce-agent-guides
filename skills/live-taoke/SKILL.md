# 活动合作利润测算

展示和交流时使用中文名「活动合作利润测算」；`live-taoke` 仅作为技术标识与分发包目录名称。

## 1. 触发 Skill

用户主动调用本 Skill，或任务涉及直播带货（自播投流、达人纯佣、达播坑位费+佣金）与淘客/团长招商等活动合作的利润、保本线与费用上限测算时使用。以用户现有文字、报价表或合作方案为输入来源，不强制要求填写固定表格。

本 Skill 仅用于单品活动合作的经营测算与边界判断，不执行真实商务签约、投流投放或替用户作最终经营决策。

## 2. 确认任务、已有数据与可交付结果

先识别用户已经提供的信息，给出简明反馈：

- 对合作模式（自播投流 / 达播纯佣 / 坑位费+佣金 / 淘客团长）与已有价格、成本数据的理解。
- 当前已有数据能够输出哪些结果（如标价与 BOM 差额、毛利、CM1 等），以及补充关键字段后可以交付什么（如活动总利润、保本销量、佣金上限、坑位费上限与情景对比）。不预先承诺缺失数据支持的指标。
- 本地操作边界：仅在本地环境读取文件、调用随附脚本与生成报告，不上传数据到外部，不修改用户原始文件，不自动安装依赖，也不保证经营决策无风险。

例如：

> 已知标价 199 元、券 20 元（实付 179 元）、BOM 与包装成本 48.5 元、运费 6.5 元、平台费率 5%。我可以先给出券后实付 179 元与履约平台后边际（CM1）115.05 元；若要测算活动总利润、保本销量、佣金与坑位费上限，还需要补充退货率、税率、达人佣金率以及坑位费/样品费与销量规划。本次仅在本地计算并输出报告，不修改原始文件，不上传数据。

确认边界后直接推进计算；只有存在影响测算口径的关键歧义时才向用户提问。

## 3. 收集必要输入，只计算有依据的部分

优先从现有材料中提取参数，只针对影响核心交付结果的缺失项提问。用户无法提供全量数据时，交付已有数据支持的指标，不反复追问。

### 字段与输入规则

- 金额均为人民币元（单件含税或固定总额）；比例均使用小数输入（如 15% 输入 `0.15`，切勿输入 `15`）。
- **标价与优惠**：`listPrice` 为商品标价；`coupon` 为优惠券金额。用户明确无券时填 `coupon: 0`；未明确时保持缺失，不把缺失当作 0 元券。实付金额为 `listPrice - coupon`。
- **销量口径区分**：
  - `expectedUnits`（预期销量）：**专门用于固定投入（坑位费与样品成本）的单件保本分摊**，不影响整场实际 GMV 与实际总利润。
  - `units`（整场实际成交件数）：**专门用于整场实际成交额、整场投流支出与整场总净利计算**。units 为非负整数，expectedUnits 为正整数。佣金、坑位费和保本 ROI 的单件边界基于 expectedUnits，不自动代表实际 units 下的整场边界。
- **固定投入扣除规则**：坑位费 `slotFee` 与样品费 `sampleCost` 为整场固定投入。整场总净利始终一次性扣除全部固定投入，即使实际成交为零，也会如实反映固定成本全额亏损，绝不按单件利润简单乘实际销量。
- **费率与税费不可猜测**：退货率、平台技术服务费率、增值税率、达人佣金率、团长服务费率必须来自用户明确说明；公司身份与纳税属性不可主观推测。税费模式 `taxMode` 支持 `'inclusive'`（含税，默认公式 `实付 × 税率 / (1 + 税率)`）与 `'exclusive'`（未税，公式 `实付 × 税率`）。
- **投流 ROI 规则**：若 `paidTrafficShare > 0`，`roi` 必须大于 `0.000001`，避免触发原引擎数值阈值内的退化行为（假定 ROI=1 或不计投流）。无投流场景必须由用户明确 `paidTrafficShare: 0`，此时 ROI 可为零或缺失。
- **缺失数据保护**：缺失字段保持缺失，脚本通过依赖门禁控制指标输出，缺失依赖的指标输出 `null` 并在 `missingByMetric` 中列明依赖项。**严禁从示例、预设场景或所谓行业均值中偷补默认值**。
- **多方案对比**：如需对比达播坑佣、纯佣或自播不同方案，可在根对象添加 `scenarios` 数组，脚本将生成横向对比表。

最小输入示例（仅有标价与 BOM）：

```json
{
  "productName": "待测算活动单品",
  "settings": {
    "listPrice": 199,
    "bomCost": 45
  }
}
```

上述输入仅能计算标价减 BOM 差额 154 元（未扣包装、退款、履约、平台、营销与税费，非利润），其余指标均为 `null` 并如实列明缺失项。

### 执行资源与命令

所有相对路径均相对于本 Skill 根目录：

- [执行入口](agent/calculate.mjs)：CLI 入口脚本，接受输入 JSON 与输出目录。
- [指标依赖检查](agent/availability.mjs)：数据依赖门禁，防止假值泄漏与未授权补值。
- [计算引擎](src/engine.ts)：复用现有活动测算与敏感度引擎，不重写第二套公式。
- [完整示例输入](agent/example-input.json)：完整场景输入参考。
- [完整结果示例](agent/example-report.md)：真实执行输出的报告展示。

执行前确认运行环境具备 Node.js 22.18+。在用户任务目录中创建输入 JSON，指定新输出目录，执行：

```bash
node "<skill-root>/agent/calculate.mjs" "<task-directory>/input.json" "<task-directory>/output"
```

stdout 返回结果 JSON；并在输出目录生成 `result.json` 与 `report.md`。

## 4. 表格和富文本报告交付结果

读取执行产出的 `report.md`，在对话中直接展示结构化内容，不只交付路径：

1. **核心结论**：明确当前数据是否支持计算活动总利润与保本线；若数据不全，先说明计算边界。
2. **核心经营指标表**：展示已具备数据支持的实付价、单件净利、整场总净利、保本销量、佣金率上限与坑位费上限。
3. **已知费用明细表**：展示单件分摊的各项已知成本与占券后实付比。
4. **敏感度情景矩阵 / 方案对比**：若数据齐全，展示退货率与佣金率/投流 ROI 的双向情景波动矩阵。退货率、佣金率按百分点 pp 变化，ROI 按相对百分比变化；比例触及边界时截断。多方案必须保留各方案实际输入，不静默继承主方案数据，缺失项显示数据不足，不能称为不可达。
5. **暂不可提供的结果与缺失项**：用通俗中文告知用户缺少的业务输入，并说明补齐后能进一步获得什么。
6. **业务口径说明**：明确注明券后全额计提、退款不回冲、单件分摊与整场只扣一次等既定口径。

### 模型核心口径备忘

- **券后全额计提且退款不回冲**：平台技术服务费、达人佣金、团长服务费与税费均按券后实付金额全额计提；发生退款时，这些费用不作冲减退还。
- **单件分摊 vs 整场总净利**：
  - 单件净利润中的固定费按 `(slotFee + sampleCost) / expectedUnits` 摊销。
  - 整场总净利为 `单件固定前边际 × units - (slotFee + sampleCost)`。固定费用在整场维度只扣除一次。
- **不可达边界**：即使佣金或坑位费为零仍亏损时，相应上限为 null 并说明原因，不能把原引擎截断出的 0 元/0% 叫作安全上限。券后金额为零时净利率不可计算。
- **ROI 退化严禁静默沿用**：付费流量占比大于 0 时，投流 ROI 必须高于引擎 `0.000001` 阈值，不把投流失利静默当作 1.0 ROI 测算。
